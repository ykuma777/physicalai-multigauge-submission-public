# 3台のゲージを自動点検し、異常箇所を指し示すロボット

実装確認済み仕様書／PAI最終課題_ykumakuma777／2026-10-27

## 1. 何をする作品か

手先カメラで既知位置のA・B・Cを順番に撮影し、画像AIが正常／異常に分類する。異常と判断した場所だけを非接触姿勢で指し示し、初期姿勢（home）に戻る。

## 2. 点検と結果の指示の違い

点検はA→B→Cの観測姿勢への移動、到達確認、新規撮影、画像AI判定。3台の結果確定後の指示は、異常と判定した対象をA・B・C順に知らせる動作である。再撮影、再判定、経時監視はしない。全台正常なら「異常なし」、指示せず初期姿勢へ戻る。

観測姿勢への到達後に新しいROS画像を取得する。画像SHA-256、run ID、撮影時刻、推論入力と表示画像の照合を記録する。机・ゲージ・手先カメラを含むMoveIt衝突検査を保ち、計画や到達が不成立なら後続を止める。画像取得・品質・推論・表示照合の失敗も停止し、自動で撮り直さず、動作命令も自動再送しない。

## 3. シグナルの意味

緑「AI判定：正常」と赤橙「AI判定：異常」は画像AIの分類であり、正解の表示ではない。灰色は判定待ち。判定不能・処理停止は理由を併記し、正常扱いしない。強調枠は現在の対象と工程を示す。「移動先への到達：確認済み」は関節状態からの到達確認、「推論画像と表示画像：一致」は画像対応の照合であり、分類の正しさを意味しない。

取得画像と判定は指示中も残す。指示姿勢への移動中と、到達確認後の「指示中」を区別する。run ID、撮影時刻、hash、SVM出力は詳細証拠。marginは正解確率・異常度ではない。A・B・Cの注釈は対象IDで、正解ラベルではない。

## 4. 3例の動作

- 例1：準備条件 NAN（A/B/C順）。実録run `mg_20261027T081621Z_813352`。画像AIの判定から選んだ指示対象：B。実際の指示順：B。初期姿勢復帰と全体成功を実行後に確認。対象準備からの所要時間 88.9 秒。
- 例2：準備条件 NAA（A/B/C順）。実録run `mg_20261027T081759Z_9a885d`。画像AIの判定から選んだ指示対象：B、C。実際の指示順：B、C。初期姿勢復帰と全体成功を実行後に確認。対象準備からの所要時間 103.1 秒。
- 例3：準備条件 NNN（A/B/C順）。実録run `mg_20261027T081951Z_e109f6`。画像AIの判定から選んだ指示対象：なし。実際の指示順：なし。初期姿勢復帰と全体成功を実行後に確認。対象準備からの所要時間 78.7 秒。

Nは正常、Aは異常を表す。条件は対象準備の情報であり、実行中の推論へ渡さない。別の条件への切替は「別の試行」と明示する。

## 5. 検証結果と限界

### 学習上の正常・異常

針がほぼ縦に見える合成画像を正常、強く傾いた合成画像を異常の学習例として作成した既存のHOG＋線形SVMを使う。これは学習例の説明であり、正常角度の連続した範囲や実設備の故障を定義するものではない。元モデルと固定ROIを保持し、各地点の実際のROS画像で確認した。

`camera_demo/configs/dataset.yaml`のtrain_angle_indices=[0,1,3,4]による正常学習角度は[-0.13,-0.08,0.02,0.07] rad、異常は[0.72,0.78,0.90,0.96] rad。検証角度は正常[-0.03,0.12] rad、異常[0.84,1.02] rad。連続した正常範囲や物理的故障の定義ではない。
